**Network Load Balancer (v2)**

- Network Load Balancers (layer 4) forward TCP and UDP traffic to your instances  
- Handle millions of requests per second  
- Ultra-low latency  
- Only NLBs provide both DNS and static IP  
- NLB has one static IP per AZ and supports assigning Elastic IPs (helpful for whitelisting specific IPs)  
- NLBs are used for extreme performance, TCP, or UDP traffic  
- It is possible to have a Network Load Balancer in front of an Application Load Balancer  
- The health checks are performed by Network Load Balancer target groups and support three kinds of protocols: TCP, HTTP, and HTTPS

**Gateway Load Balancer**

- Used to deploy, scale, and manage a fleet of third-party network virtual appliances in AWS, e.g. firewalls, intrusion detection/prevention systems, deep packet inspection systems, payload manipulation.  
- Operates at layer 3 (network layer) for IP packets  
- Combines a transparent network gateway and a load balancer

**Gateway Target Groups:**

- EC2 instances   
- IP addresses

**Elastic Load Balancer Sticky Sessions (Session Affinity)**

- It is possible to implement stickiness so that the same client is always redirected to the same instance behind a load balancer  
- This works for Classic Load Balancer, Application Load Balancer, and Network Load Balancer  
- The "cookie" used for stickiness has an expiration date you can control  
- Use case: make sure the user does not lose session data  
- Enabling stickiness may bring imbalance to the load across the backend EC2 instances

**2 Types of Cookies**

- **Application-based cookies:** custom cookie name, generated by the target, can have custom attributes, must be specified individually for each target group. Application cookie: generated by the load balancer  
- **Duration-based cookies**: cookies are generated by the LB

**Cross-Zone Load Balancing** 

- With cross-zone load balancing, each load balancer instance distributes evenly across all registered instances in all AZs  
- Application Load Balancer: cross-zone is enabled by default (can be disabled at the target group level). No charges for inter-AZ data  
- Network Load Balancer and Gateway Load Balancer: disabled by default. You pay charges for inter-AZ data if enabled  
- Classic Load Balancer: disabled by default

**SSL/TLS Basics**

- A certificate allows traffic between your clients and your load balancer to be encrypted while in transit. This is called in-flight encryption. That means the data as it goes through a network is encrypted and can only be decrypted by the sender and the receiver.   
- SSL refers to Secure Sockets Layer and is used to encrypt transfer connections.   
- TLS is the newer version of SSL and refers to Transport Layer Security.  
- You can manage certificates using ACM (AWS Certificate Manager)  
- You can also upload your own certificates  
- HTTPS listener: you must specify a default cert; clients can use SNI (Server Name Indication) to specify the hostname they reach

**SSL - Server Name Indication (SNI)**

- SNI solves the problem of loading multiple SSL certs onto one web server (to serve multiple websites)  
- It is a new protocol and requires the client to indicate the host name of the target server in the initial SSL handshake  
- The server will then find the correct certificate or return the default one  
- Note: only works for ALB and NLB (new gens), and CloudFront

**Connection Draining**

- Feature naming:  
  - Connection draining for CLB  
  - Deregistration delay for ALB and NLB

- Time to complete in-flight requests while the instance is deregistering or unhealthy  
- Stops sending new requests to EC2 instances that are deregistering  
- Between 1 and 36000 (default 300) and can be disabled

**Auto Scaling Group**

- This lets you create and get rid of servers very quickly  
- The goal of an Auto Scaling Group is to scale out (add EC2 instances) to match increased load and to scale in (remove EC2 instances) to match decreased load. It also ensures that we have a minimum and maximum number of EC2 instances running, automatically registers new instances to a load balancer, and recreates an EC2 instance if the previous one is terminated, e.g. unhealthy  
- ASGs are free (you only pay for EC2 instances)  
- Works with load balancers   
- ELB can check the health of EC2 instances, which can be passed to ASG to terminate instances if unhealthy  
- It is possible to scale ASGs using CloudWatch alarms

**Auto Scaling Group Scaling Policies**

- Dynamic scaling  
  - Target tracking scaling: simple to set up  
  - Simple/step scaling: uses CloudWatch  
- Scheduled scaling  
  - Anticipate scaling based on known usage patterns
- Predictive scaling  
  - Continuously forecast load and schedule scaling ahead

**Good Metrics to Scale On**

- CPUUtilization  
- RequestCountPerTarget  
- Average network I/O  
- Or any custom metric using CloudWatch
